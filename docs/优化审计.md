# 优化审计 · 对比同机型其他方案

> 调研时间：2026-10-29
> 对象：GitHub 上 4 个编译 JDCloud RE-SS-01 / AX1800 Pro 的公开工程
> 目的：找出我们这套 Kwrt 工程还能补什么、哪些坑别人已经踩过

## 二、逐项对比

### 2.1 内核与编译优化

| 项 | 别人 | 我们 | 评估 |
|---|---|---|---|
| `KERNEL_CC_OPTIMIZE_FOR_SIZE` | EmptyGhost 用 **PERFORMANCE**（`-O2`） | **SIZE**（`-Os`） | **保持 SIZE**。6 MiB 硬限制下，`-O2` 会让内核涨 100–200 KB，换来的性能提升 <3%，不划算 |
| `TARGET_OPTIMIZATION` | EmptyGhost `-Os -pipe -mcpu=cortex-a53` | 未显式设，走上游默认 | **不用改**。OpenWrt 默认已经是 `-Os -pipe -mcpu=...`，显式写一遍只是好看 |
| `KERNEL_SIZE` | NatserverWrt 改 `6144k → 12288k` | 6144k | **不建议**。见 2.4 |
| `EXTRA_CFLAGS="-Wno-error"` | alansdragon0 有 | 无 | **可加**。编译容错，个别包因警告失败时不至于整轮挂掉 |
| `CONFIG_KERNEL_WERROR` | — | `n`（common 里已设） | 已有，够了 |
| `CONFIG_CCACHE` | — | `y` | 已有，二次编译快很多 |

### 2.2 软件包差异

| 包 | 谁有 | 我们 | 评估 |
|---|---|---|---|
| `cpufreq` + `luci-app-cpufreq` | LibWrt `DEFAULT_PACKAGES` 自带 | **已在**（继承自 LibWrt） | 无需加 |
| `irqbalance` | istoreos | 无 | **可选**。NSS 硬件卸载后中断本来就少，irqbalance 可能把中断摊到小核反而变差。想试就加，不加也不亏 |
| `TURBOACC_INCLUDE_BBR_CCA` | alansdragon0 | 无（只有 `NO_FASTPATH`） | **推荐加**。让 turboacc 界面能切 BBR 拥塞控制，已有 `kmod-tcp-bbr` 打底 |
| `kmod-usb3` / `usb-dwc3` | LibWrt 默认 | **已在** | 亚瑟没 USB 口，但装了无害 |
| `wireless-regdb` | 上游 `package/firmware/` | 在默认包链里 | 已有 |
| `luci-app-store`(iStore) | istoreos | **已在**（这版加的） | 一致 |
| Docker 全家 | 都没有 | 明确不装 | 一致（1G 跑 Docker 吃力） |

### 2.3 镜像校验

`alansdragon0` 的 `check-image-layout.sh` 做法值得学：**在固定偏移处读 magic 验证 squashfs 起点**。

```bash
factory_split=$((12 * 1024 * 1024))          # 他的内核 12M
magic=$(dd if=factory.bin bs=4 skip=$((factory_split/4)) count=1 status=none | od -An -tx1)
[ "$magic" = "68737173" ] || exit 1          # "hsqs"
```

我们现在只校验 FIT 头（`od -j4` 读 totalsize），没校验内核/rootfs 的边界。**建议补上**：在 6 MiB 偏移处读 `hsqs`，能验证 squashfs 确实紧接在内核之后，而不是靠 FIT 头推算。

### 2.4 12M 内核：别人的做法与风险

NatserverWrt 直接改了：

```bash
sed -i '/^define Device\/jdcloud_re-ss-01$/,/^endef$/s/KERNEL_SIZE := 6144k/KERNEL_SIZE := 12288k/' \
  target/linux/qualcommax/image/ipq60xx.mk
```

**但这只是改了镜像打包的切分点，不等于能刷进去。** 他那条注释写得很清楚：「照抄 istoreos 方案: HLOS12M GPT + U-Boot `/big.html`」。

也就是说必须配套：

1. 换一份 `0:HLOS` = 12 MiB 的 GPT（`/img.html` 刷）
2. rootfs 起点后移 6 MiB
3. U-Boot 的 `validate_file_size` 才会放行

**风险**：GPT 刷错 = 直接变砖，得靠 TTL 或编程器救。而我们当前内核 4.79 MiB / 6 MiB，余量 1238 KiB，**没有任何必须扩的理由**。所以维持 6144k。

## 四、建议清单

### A 级 · 推荐做（低风险、有实际收益）

| # | 改动 | 收益 | 风险 |
|---|---|---|---|
| A1 | turboacc 加 `CONFIG_PACKAGE_TURBOACC_INCLUDE_BBR_CCA=y` | 界面可切 BBR，弱网/高延迟链路吞吐更好 | 无 |
| A2 | 镜像校验补 `6 MiB 处 hsqs magic` | 能验证内核/rootfs 边界，防 FIT 头与实际布局不符 | 无 |
| A4 | 无线设 `disassoc_low_ack='0'` | 不再因为丢几个包就踢客户端（老设备掉线主因之一） | 无 |
| A5 | Release 说明补 manifest 摘要（包数量 + 关键包版本） | 刷前就知道里面有什么 | 无 |

> **进度（2026-10-29）**：A5 **已部分落地** —— Release 说明现在会带本次构建用到的上游 sha、默认值表、以及「SSH 两条命令在线升级」的写法；Release 额外附固定文件名 `sysupgrade.bin` / `factory.bin`，让 `releases/latest/download/` 永远指向最新版。manifest 包数量摘要尚未加（要等首次成功构建拿到 `*.manifest` 才能确定字段格式）。A1、A2、A4 未做；**原 A3（`country='CN'`）已降级为 C6**，理由见下。

### B 级 · 可选（看需求）

| # | 改动 | 说明 |
|---|---|---|
| B1 | `irqbalance` | 想试多核中断均衡就加，NSS 场景收益不确定 |
| B2 | 5G 固定 `channel=149` | 避免 ACS 选到 DFS 信道；但邻居换环境时不如 auto 灵活 |
| B3 | `ieee80211w=1`（PMF optional） | WPA2 下也能用管理帧保护，老设备兼容性尚可 |
| B4 | 2.4G `cell_density=2` | 密集住宅区吞吐更好，但抗干扰变差 |
| B5 | zram 设 256 MB | 1G 内存更从容；默认值偏小 |
| B6 | `EXTRA_CFLAGS="-Wno-error"` | 编译容错兜底 |

### C 级 · 不建议

| # | 改动 | 原因 |
|---|---|---|
| C1 | 12M 内核 | 必须换 GPT，刷错变砖；当前余量 1238 KiB 够用 |
| C2 | 内核改 `-O2` | 涨 100–200 KB 换 <3% 性能，不值 |
| C3 | `CONFIG_ALL_NONSHARED=y` | 编 897 个包，4 核 6–10 小时且易爆盘 |
| C4 | Docker / iStore Router | 1G 运存吃力 |
| C5 | `CONFIG_TARGET_ROOTFS_PARTSIZE` 调大 | 你已手工扩到 2G，镜像里写 1004 正好 |
| C6 | 无线设 `country='CN'`（原 A3） | 对 ath11k 后果静态推不出来：它不走内核 regdb，功率/信道由 BDF 的 CTL 表决定，可能掉功率或掉信道。详见五章末 |

## 五、具体改法（A 级定稿 + C6 说明）

### A1 turboacc BBR

`devices/qualcommax_ipq60xx/.config`：

```ini
CONFIG_PACKAGE_luci-app-turboacc=y
CONFIG_PACKAGE_TURBOACC_INCLUDE_NO_FASTPATH=y
CONFIG_PACKAGE_TURBOACC_INCLUDE_BBR_CCA=y     # 新增
```

### A2 镜像校验

`.github/workflows/build.yml` 的「复核内核体积」步骤后追加：

```bash
# 校验 6 MiB 处是 squashfs 起点（hsqs），确认内核/rootfs 边界
magic=$(dd if="$f" bs=4 skip=$((6*1024*1024/4)) count=1 status=none | od -An -tx1 | tr -d ' \n')
[ "$magic" = "68737173" ] || { echo "::error::6MiB 处不是 hsqs（$magic），镜像布局异常"; exit 1; }
```

### A4 无线

`99-ax1800` 的 WiFi 段追加：

```sh
uci -q set "wireless.@wifi-iface[$i].disassoc_low_ack='0'"
```

### A5 Release 摘要

在发布步骤里补：

```bash
pkgs=$(wc -l < *.manifest)
echo "| 包数量 | $pkgs |" >> release.md
grep -E '^(luci-app-openclash|luci-theme-argon|kmod-wireguard|dnsmasq-full) ' *.manifest >> release.md
```

### C6 为什么不做 `country='CN'`

**现状不是"没设"，是设成了空串**。上游 `mac80211.uc:105` 是 `set ${s}.country='${country || ''}'`，而 `country` 只从 `board.json` 的 `wlan.defaults.country` 取；这台机器的 board.json 没这个字段，所以生成的是 `option country ''`。空串 = **完全不发法规提示**（不 `iw reg set`、hostapd 也不带 `country_code=`），ath11k 用 `board-2.bin` 里出厂校准的默认 CTL 表。

**改成 `CN` 之后的事推不出来**，因为：

1. **ath11k 是 self-managed regulatory 设备**（`REGULATORY_WIPHY_SELF_MANAGED`），不走内核 `wireless-regdb`。`devices/common/diy.sh` 里 wget 的 immortalwrt `600-custom-change-txpower-and-dfs.patch`（把 CN 的 2.4G 提到 30dBm、5G 5150–5350 合并成 160MHz 并去掉 DFS 标记）**对它基本无效**，别拿那个补丁当"设 CN 没风险"的依据。
2. 实际功率/信道由 `ipq-wifi-jdcloud_re-ss-01` 提供的 `board-2.bin` 里 CN 行的 maxEIRP 与 NO-IR 标记决定，静态看不到。三种可能后果：
   - **掉功率**（最常见）：2.4G 常见从 30dBm 档掉到 20dBm，穿墙变差
   - **掉信道**：若 CN 行把 149–165 标成 NO-IR，hostapd 直接拒绝在该信道开 AP
   - 与 `htmode=HT40` 打架：CN 只到 13 信道，ACS 选到 12/13 时边带算不出来，日志报 `40 MHz not allowed`，退回 20MHz
3. 开 country 会在 beacon 里广播 802.11d 的 Country IE，个别 iOS 对不匹配的 IE 会限速。

**结论**：收益是个合规标签，代价可能是掉功率/掉信道，而且多半刷完才发现。真要试，把不确定性锁死：`country='CN'` + 5G 固定 149（非 DFS）+ 2.4G 固定 1/6/11，但这与 B2「留 ACS」冲突，只能二选一。

验证命令：

```sh
iw reg get                                  # 看是否真吃到 CN
iw list | grep -A6 Frequencies              # 看 5G 哪些是 *no IR*
iwinfo radio0 txpower                       # 看实际功率
dmesg | grep -iE "regd|ctl|no ir"
```

> 顺带一个能解释"脚本一挂就没 WiFi"的细节：同一段代码里 `set ${si}.disabled='${defaults ? 0 : 1}'` 且 `if (!country && band_name != '2g') defaults = null;` —— **没有国家码时 5G 的默认接口生成出来就是 `disabled=1`**。所以 `99-ax1800` 必须显式写 `disabled=0`，而它一旦语法错，5G 连开都不会开。

## 六、总结

**我们的配置在同机型里已经属于偏激进的一档**——NSS 内存档、q6 扩展、去推广去外链这些别人都没做。真正值得补的只有 4 个小项（A1、A2、A4、A5），都是低风险微调，不动内核、不动分区。

12M 内核虽然诱人，但代价是换 GPT，而当前 1238 KiB 余量根本用不完，属于"为了改而改"。
